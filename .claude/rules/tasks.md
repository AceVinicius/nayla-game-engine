# Task Rules

A task defines:
- primary agent;
- required/optional context;
- dependencies;
- objective;
- requirements;
- acceptance criteria;
- tests;
- non-goals;
- review requirement.

## Context Budget

Prefer:
- 1 task;
- 1–2 domain rules;
- 1 relevant spec;
- specific source files.

Do not duplicate specification text inside tasks.

## Escalation

Architecture ambiguity → `architect`
GPU abstraction ambiguity → `gpu-architect`
Specification ambiguity → `spec-writer`
Task decomposition ambiguity → `task-planner`
